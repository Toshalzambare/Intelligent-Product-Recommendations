# Intelligent Product Recommendation & Market Basket Analyzer 🛒

This project is a full-stack data mining application that analyzes historical customer transactions to discover hidden purchasing patterns. Using **Unsupervised Machine Learning** (specifically Association Rule Mining), the system automatically learns which products are frequently bought together and utilizes these insights to power a robust product recommendation engine.

---

## 🌟 Key Features

* **Single & Multi-Product Recommendations**: Suggests products to users based on one or multiple items currently in their cart.
* **Association Rule Explorer**: A dynamic interface allowing users to filter thousands of rules in real-time based on minimum Support, Confidence, and Lift.
* **Interactive Analytics Dashboard**: Visualizes top-selling product combinations, confidence vs. lift scatter plots, and network graphs using Plotly.
* **Algorithm Comparison**: Benchmarks the runtime and memory efficiency of the **Apriori** algorithm vs. the **FP-Growth** algorithm.

---

## 🧠 Machine Learning & Data Mining Pipeline

The project follows a rigorous data mining pipeline to convert raw CSV transactions into intelligent recommendations:

1. **Data Cleaning**: Drops missing values, removes cancelled orders (invoices starting with 'C'), and standardizes text.
2. **Transaction Formation**: Groups individual product purchases by `InvoiceNo` to create discrete "Market Baskets".
3. **One-Hot Encoding**: Transforms the transaction lists into a sparse boolean matrix using `TransactionEncoder`.
4. **Frequent Itemset Mining**: Uses the highly efficient **FP-Growth** algorithm to find frequent combinations of items.
5. **Rule Generation**: Extracts Association Rules from the frequent itemsets based on strict Confidence thresholds.

### The Algorithms

This project implements and compares two primary algorithms:

#### 1. Apriori Algorithm
The classic association rule algorithm. It uses a "generate-and-test" strategy, scanning the dataset multiple times to find itemsets of length 1, then length 2, and so on. 
* **Drawback**: On large E-commerce datasets, Apriori suffers from a combinatorial explosion during candidate generation, making it incredibly slow.

#### 2. FP-Growth (Frequent Pattern Growth)
A modernized approach that uses a "divide-and-conquer" strategy. It compresses the dataset into a highly compact **FP-Tree** structure in memory.
* **Advantage**: It only requires exactly **two dataset scans**, bypassing candidate generation entirely. This makes FP-Growth exponentially faster than Apriori on large datasets, which is why it is used to power this application's backend.

### Association Rule Metrics

The recommendation engine ranks products using three core mathematical metrics:

* **Support**: How frequently the specific combination of products appears in the entire dataset. (e.g., *How often are Laptops and Mice bought together overall?*)
* **Confidence** (Accuracy): The probability that the *Consequent* will be purchased given that the *Antecedent* was purchased. (e.g., *If they bought a Laptop, there is an 85% chance they will buy a Mouse*). **We filter for >50% confidence to ensure highly reliable recommendations.**
* **Lift**: How much more likely the items are bought together compared to if they were bought randomly and independently. A Lift > 1 indicates a positive, strong association.

## 🏗️ System Architecture

The application is decoupled into a backend API and a frontend UI:

```text
Streamlit (Frontend UI)
       │ (REST HTTP Requests)
       ▼
FastAPI (Backend Server)
       │ (Loads pre-trained .pkl artifacts)
       ▼
Recommendation Engine (Rule filtering & mapping)
```

1. **Models Directory**: Houses the `.pkl` files (frequent itemsets, association rules, product mappings) generated by the training notebook.
2. **FastAPI Backend**: Loads the models into memory at startup. Exposes REST endpoints (`/recommend`, `/rules`, `/analytics`) for lightning-fast querying.
3. **Streamlit Frontend**: Provides the interactive web application that communicates with the backend.

## 🚀 Setup & Installation (Local)

### Prerequisites
* Python 3.9+
* A transaction dataset (like the [Kaggle E-Commerce Data](https://www.kaggle.com/datasets/carrie1/ecommerce-data)) placed at `data/transactions.csv`.

### 1. Install Dependencies
Create a virtual environment and install the required packages:
```bash
python -m venv venv
venv\Scripts\activate      # On Windows
source venv/bin/activate   # On Mac/Linux
pip install -r requirements.txt
```

### 2. Train the Models
Before starting the servers, you must generate the machine learning models. 
Run the `train_models.py` script:
```bash
python train_models.py
```
*(Alternatively, you can run the `notebooks/01_EDA_and_Training.ipynb` Jupyter Notebook).*

### 3. Launch the Application
If you are on Windows, you can simply double-click the **`run_app.bat`** file. This script will automatically:
1. Activate your virtual environment.
2. Start the FastAPI backend on Port 8000.
3. Start the Streamlit frontend on Port 8501.
4. Open the application in your browser.

If you are starting them manually:
```bash
# Terminal 1 (Backend)
uvicorn backend.app:app --reload

# Terminal 2 (Frontend)
streamlit run frontend/streamlit_app.py
```
